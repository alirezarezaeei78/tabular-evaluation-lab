# Declared protocol — 16 October 2026

Task: help an analyst inspect exact selected-feature matches and repeated entity/group identifiers across existing train/test CSV files before model evaluation. New contribution: a local standard-library CLI/API with explicit canonicalization, collision-safe equality, source-row evidence, machine-readable JSON/CSV warnings and CI exit codes. No automatic row removal or split repair. Established methods, no new algorithm or scientific novelty claim.

Primary metrics: number of test rows whose selected feature tuple appears in training; shared feature keys; number of test rows whose explicit group appears in training; shared groups. Distinguish these warnings from proof of invalid leakage. Exact common feature values can occur in independent groups. A no-overlap finding is not a general safety certificate.

Canonicalization declared before implementation: CSV strings; text cells normalize Unicode NFC but preserve whitespace and case; empty string is missing. Explicit numeric columns use finite Decimal values with exact coefficient/exponent canonicalization, normalize signed zero and equivalent decimal notation, and strip surrounding whitespace. No tolerance rounding, imputation, inferred numeric types or label-based fingerprinting. Reject nonfinite numeric cells, malformed rows/headers, missing required columns, an included target, duplicate feature names and empty data. Blank group identifiers are rejected. A row with all selected features missing is allowed but counted and warned about. Group identity uses NFC exact text, no trimming/casefolding. Hashes identify canonical byte strings; equality must verify the canonical bytes so simulated hash collisions cannot create false matches. Reports contain row positions and fingerprints, not raw feature/group values. Hashes are not anonymization and reports remain local by default.

Declared experiment: 200 synthetic entities, three rows per entity (600 total). Two records repeat one selected numeric/text feature tuple; a third record has a distinct numeric feature. Group identity is separate from features. Targets and row IDs are excluded from fingerprints. Generate authored data deterministically with seed 20261016. Use three preset partition seeds 13, 29 and 47. For each seed compare (1) unchecked random row partition, test fraction 0.30; (2) feature-key partition, selecting 30% of unique feature keys; (3) group partition, selecting 30% of entities. All original rows remain assigned exactly once. Partitions need not contain identical test rows or sizes; this is a split-auditing stress test, not a matched predictive-performance experiment.

Use independent generator metadata (latent feature-key/entity IDs) to compute expected row/group intersections without using the auditor's canonicalizer or hashes. Retain all nine reports, split memberships, expected/actual counts, input hashes and per-row flags. Compare an unchecked zero-warning baseline against the known intersections; do not invent model accuracy, latency, confidence intervals or scientific validation. An additional manually declared cross-group common-value fixture has two training and two test rows, zero shared entity IDs and one shared feature tuple; it demonstrates that feature overlap alone is not proof of contamination.

Tests: numeric equivalents/signed zero/large precision; nonfinite and malformed numeric data; Unicode equivalence, case/whitespace distinction, missing-vs-literal text; column order invariance, target exclusion, duplicates/multiplicity, groups and missing group; empty/header-only/bad CSV/ragged rows; identical outputs/no input mutation; forced digest collision; JSON/CSV round trips with exact counts; CLI clean/overlap/error exit status and both documented workflows. Reproducibility checks require identical substantive results/memberships on rerun and preserved source input bytes. Core runtime is Python 3.12 standard library; plotting is a separate dependency.

Limits: exact declared equivalence only; no near-duplicate, time/availability, target-proxy or unrecorded entity detection. One small authored fixture family, visible during development, is functionality testing, not independent enterprise validation. A matching group may be appropriate for some within-group tasks; analysts must choose the evaluation question. Files and reports are local-only; no hosted demo or browser UI is claimed. Keep complete local work if authentication or native duplicate checking is unavailable.
